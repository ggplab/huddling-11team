# 해커톤 진행 절차와 지난 복기

조장(임정)이 지난 해커톤에서 쓴 절차와 복기를 오늘 실험(약 2시간, 발표 뒤 참가자 전원 투표)에 맞게 줄였습니다.
원문 후기는 [같이보기에 늦게 온 시청자, AI가 대신 답한다](https://buildnwrite.com/blog/watch-party-host-hackathon/)에 있습니다.

## 오늘 쓸 절차

| 단계 | 시간 | 하는 일 | 끝났다는 판정 |
|---|---|---|---|
| 0. 심사 읽기 | 0~5분 | 트랙, 제출 방식, 발표 시간, 투표 기준을 한 줄씩 `docs/plan.md`에 옮깁니다. 모르는 것은 운영진에게 바로 묻습니다 | `plan.md`에 트랙과 발표 시간이 적혀 있다 |
| 1. 한 장면 정하기 | 5~15분 | "1분 안에 보여 줄 한 장면"을 먼저 정합니다. 그 장면에 필요한 화면만 화면 목록에 올립니다. 서비스 이름도 지금 정합니다 | 주제 한 문장, 이름, 화면 목록, 담당이 있다 |
| 2. 만들기 | 15~95분 | 각자 자기 화면을 만듭니다. 30분마다 PR을 올립니다. 조장은 머지와 배포를 합니다 | 배포 주소에서 한 장면이 처음부터 끝까지 눌린다 |
| 3. 확인 | 95~110분 | 새 기능을 넣지 않습니다. 배포 주소를 시크릿 창에서 열어 시연 순서대로 누르고 깨진 곳만 고칩니다 | 시연 순서 전체가 오류 없이 한 번 돌았다 |
| 4. 발표 | 110분~ | 문제 한 문장, 한 장면 시연, 다음에 할 것 한 줄 순서로 말합니다 | 발표자가 배포 주소로 한 번 연습했다 |

## 구글 해커톤에서 배운 것

2026-10-16 Google DeepMind AI Hackathon에 Watch Party Host라는 앱으로 나갔고 수상하지 못했습니다. 수상작을 보고 정리한 내용입니다.

| 그날 본 것 | 오늘 적용 |
|---|---|
| 심사는 사업 기획보다 실제로 도는 프로토타입을 봤습니다 | 시장 조사와 수치에 시간을 쓰지 않습니다. 문제 설명은 한 문장으로 끝냅니다 |
| 2~4위는 모두 1분 안에 놀라운 장면이 바로 보이는 제품이었습니다 | 기획의 첫 산출물을 "1분 안에 보여 줄 한 장면"으로 정합니다 |
| 우리 제품은 상황을 먼저 설명해야 가치가 보였습니다 | 설명 없이 화면만 봐도 무엇인지 알 수 있는 것을 고릅니다 |
| 하루의 70%를 기획에 썼는데, 기획이 겨눈 곳이 심사 방식과 달랐습니다 | 기획은 15분 안에 끝내고 만드는 데 시간을 줍니다 |
| 미리 써 둔 대본으로 돌린 시연은 놀라움이 약했습니다 | 실제로 입력해서 결과가 나오는 장면을 보여 줍니다 |
| 수상작 하나는 AI가 만드는 부분과 검증하는 부분을 나누고, 핵심 계산은 코드로 고정했습니다 | AI가 필요한 곳과 코드로 계산할 곳을 나눠 정합니다 |
| 이름을 기획 단계에서 정하지 않았습니다 | 1단계에서 이름을 정합니다 |
| API 키 두 개가 차례로 한도에 걸렸고, 어느 기능이 어느 키를 쓰는지 몰라 한동안 혼란스러웠습니다 | 키와 결제 경로는 하나로 두고 조장만 관리합니다 |
| 발표 자료와 대본은 제출 30분 전에 동결했습니다 | 95분에 동결하고 그 뒤로는 깨진 곳만 고칩니다 |

## 시연과 발표에서 지킬 것

- 기능마다 클릭 한 번에 한 가지가 보이게 만듭니다.
- 배포 주소는 새 탭이나 시크릿 창으로 열어 확인합니다. 내 컴퓨터에서만 되는 상태를 걸러 냅니다.
- 재 보지 않은 주장은 발표에 넣지 않습니다. "가장 빠르다", "어디에도 없다" 같은 말이 여기에 듭니다.
- 미리 넣어 둔 데이터로 시연하면 "시연용 데이터"라고 말합니다.
- 행사 전에 준비한 것은 숨기지 않고 밝힙니다.
- 발표 화면에 API 키, 이메일, 실명이 보이지 않게 합니다.

## 제출 전 확인

- [ ] 배포 주소가 시크릿 창에서 열린다
- [ ] 시연 순서를 처음부터 끝까지 한 번 눌러 봤다
- [ ] `README.md`에 서비스 한 문장과 배포 주소가 있다
- [ ] 마감 시각 전에 제출했다
