# 해커톤 진행 절차와 지난 복기

조장(임정)이 지난 두 대회(구글 해커톤, 카카오 AI_TOP_100 예선)에서 쓴 절차와 복기를 오늘 실험(제출 마감 14:20, 팀당 1분 스피치 뒤 참가자 전원 투표)에 맞게 줄였습니다.
구글 해커톤 후기는 [같이보기에 늦게 온 시청자, AI가 대신 답한다](https://buildnwrite.com/blog/watch-party-host-hackathon/)에 있습니다.

## 오늘 쓸 절차

제출 마감은 14:20입니다. 규칙 원문 정리는 [event-rules.md](event-rules.md)에 있습니다.

| 단계 | 시각 | 하는 일 | 끝났다는 판정 |
|---|---|---|---|
| 0. 심사 읽기 | 시작 직후 5분 | 트랙, 제출 방식, 발표 시간, 투표 기준을 기획서에 옮깁니다. 모르는 것은 운영진에게 바로 묻습니다 | 기획서에 트랙과 제출 마감이 적혀 있다 |
| 1. 한 장면 정하기 | 다음 15분 | "1분 안에 보여 줄 한 장면"을 먼저 정합니다. 핵심 기능은 1개만 남깁니다. 서비스 이름도 지금 정합니다 | 한 줄 기획, 이름, 화면 목록, 담당이 있다 |
| 2. 만들기 | 13:50까지 | 각자 자기 화면을 만듭니다. 30분마다 PR을 올립니다. 조장은 머지와 배포를 합니다 | 배포 주소에서 한 장면이 처음부터 끝까지 눌린다 |
| 3. 확인 | 13:50~14:10 | 새 기능을 넣지 않습니다. 배포 주소를 시크릿 창과 휴대폰에서 열어 시연 순서대로 누르고 깨진 곳만 고칩니다 | 시연 순서 전체가 오류 없이 한 번 돌았다 |
| 4. 제출과 발표 준비 | 14:10~14:20 | 배포 링크를 제출합니다. 스피치 1명과 조작 1명이 1분 발표를 한 번 맞춰 봅니다 | 14:20 전에 제출했고 1분 안에 끝난다 |

## 구글 해커톤에서 배운 것

2026-10-16 Google DeepMind AI Hackathon에 Watch Party Host라는 앱으로 나갔고 수상하지 못했습니다. 수상작을 보고 정리한 내용입니다.

| 그날 본 것 | 오늘 적용 |
|---|---|
| 심사는 사업 기획보다 실제로 도는 프로토타입을 봤습니다 | 시장 조사와 수치에 시간을 쓰지 않습니다. 문제 설명은 한 문장으로 끝냅니다 |
| 2~4위는 모두 1분 안에 놀라운 장면이 바로 보이는 제품이었습니다 | 기획의 첫 산출물을 "1분 안에 보여 줄 한 장면"으로 정합니다 |
| 우리 제품은 상황을 먼저 설명해야 가치가 보였습니다 | 설명 없이 화면만 봐도 무엇인지 알 수 있는 것을 고릅니다 |
| 하루의 70%를 기획에 썼는데, 기획이 겨눈 곳이 심사 방식과 달랐습니다 | 기획은 20분 안에 끝내고 만드는 데 시간을 줍니다 |
| 미리 써 둔 대본으로 돌린 시연은 놀라움이 약했습니다 | 실제로 입력해서 결과가 나오는 장면을 보여 줍니다 |
| 수상작 하나는 AI가 만드는 부분과 검증하는 부분을 나누고, 핵심 계산은 코드로 고정했습니다 | AI가 필요한 곳과 코드로 계산할 곳을 나눠 정합니다 |
| 이름을 기획 단계에서 정하지 않았습니다 | 1단계에서 이름을 정합니다 |
| API 키 두 개가 차례로 한도에 걸렸고, 어느 기능이 어느 키를 쓰는지 몰라 한동안 혼란스러웠습니다 | 키와 결제 경로는 하나로 두고 조장만 관리합니다 |
| 발표 자료와 대본은 제출 30분 전에 동결했습니다 | 13:50에 동결하고 그 뒤로는 깨진 곳만 고칩니다 |

## 카카오 AI_TOP_100 예선에서 배운 것

2026-10-31 카카오 AI_TOP_100 2026 예선에 나갔습니다. 다섯 시간 동안 카카오톡 상담 에이전트를 만드는 과제였습니다. 관계자 10명에게 479번 질문해 지식을 모았고(평균 발굴률 82.8%), 제출 전 공개 시험은 53건 중 45건을 맞혔습니다. 본선에는 오르지 못했습니다.

### 잘된 것

| 그날 한 것 | 오늘 적용 |
|---|---|
| 심사 5항목을 시험 지표로 먼저 옮겼습니다 | 투표 기준을 먼저 읽고, 그 기준으로 우리 화면을 스스로 채점해 봅니다 |
| 세션 일곱 개가 동시에 돌았지만, 세션마다 쓰는 폴더를 나눠 두었습니다 | 한 사람이 파일 하나를 맡는 규칙이 같은 원리입니다 |
| 처음 보는 문제로 따로 시험하자 정답률이 88%에서 50%로 떨어졌고, 그 덕에 빠진 곳을 찾았습니다 | 만든 사람이 아닌 조원이 아무 값이나 넣어 보게 합니다 |
| 주 모델을 일부러 끊어 대체 경로가 도는지 확인했습니다 | AI 호출이 실패했을 때 화면에 무엇이 보일지 미리 정합니다 |
| 오래 돈 세션의 성능이 떨어지자 인계 문서를 쓰고 새 세션으로 바꿨고, 그 뒤 지표가 74.4에서 82.8로 올랐습니다 | Claude Code 대화가 길어져 헤매면 새 대화를 열고 `CLAUDE.md`부터 다시 읽게 합니다 |

### 시간을 잃은 곳

| 병목 | 크기 | 오늘 적용 |
|---|---|---|
| 사람 손을 거치는 왕복 | 후반 119분 중 손 입력 61분, 기다림 58분. 손 입력 622건 | 복사해 붙이는 일과 기다리는 일이 보이면 바로 말해서 줄입니다 |
| 심사 기준 대조와 실제 경로 시험이 늦음 | 시작 2시간 3분 뒤에 첫 대조, 2시간 36분 뒤에 첫 실제 경로 시험 | 첫 30분 안에 배포 주소에서 화면 하나를 실제로 열어 봅니다 |
| 같은 지시를 세 번 함 | 정한 규칙을 문서에 적지 않아 세션이 바뀔 때마다 사라졌습니다 | 정한 규칙은 조장이 바로 `CLAUDE.md`에 적습니다 |
| 받은 문서를 늦게 읽음 | 답이 들어 있던 문서를 받고 쓰기까지 40분이 걸렸습니다 | 받은 자료와 링크는 받은 즉시 열어 봅니다 |
| 동결 뒤에도 고침 | 동결을 선언한 뒤 다섯 번 다시 올렸고, 측정한 판과 제출한 판이 달랐습니다 | 동결 뒤에 고치면 시연 순서를 처음부터 다시 눌러 봅니다 |
| 마감을 두 번 미룸 | 18분을 더 써서 얻은 것은 1.9점이었습니다 | 마지막 한 바퀴의 이득은 작습니다. 그 시간은 시연 연습에 씁니다 |

### 만들기 전에 답할 네 질문

1. 형식이 정해지지 않은 입력은 무엇이고, 어떻게 넓게 받는가
2. 핵심 입력이나 도구가 실패하면 사용자에게 무엇을 보여 주는가
3. 답이 나가기 전에 무엇을 코드로 막는가
4. 시험은 누가, 무엇을 모른 채 짜는가

## 시연과 발표에서 지킬 것

- 기능마다 클릭 한 번에 한 가지가 보이게 만듭니다.
- 배포 주소는 새 탭이나 시크릿 창으로 열어 확인합니다. 내 컴퓨터에서만 되는 상태를 걸러 냅니다.
- 재 보지 않은 주장은 발표에 넣지 않습니다. "가장 빠르다", "어디에도 없다" 같은 말이 여기에 듭니다.
- 미리 넣어 둔 데이터로 시연하면 "시연용 데이터"라고 말합니다.
- 행사 전에 준비한 것은 숨기지 않고 밝힙니다.
- 발표 화면에 API 키, 이메일, 실명이 보이지 않게 합니다.
