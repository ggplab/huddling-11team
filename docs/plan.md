# 커밋 레이스: 화면별 파일과 담당

기획 원문(아이디어, 한 줄 기획, 역할과 이름, 1분 스피치)은 [11조 기획서 구글 문서](https://docs.google.com/document/d/1UQZkKSWryCxSvNgF70BIAl1eAhRrEilyXJA-WDCxDKk/edit)에 있습니다.
기획서는 조원 누구나 고칠 수 있습니다. 이 파일에는 코드 작업에 필요한 것만 두고, 이 파일은 조장만 고칩니다(여러 사람이 고치면 충돌이 납니다).

## 주제

- 트랙: D 자유 (GitHub API를 쓰는 관제판. 조에서 트랙을 확정하면 이 줄을 고칩니다)
- 한 줄 기획: 해커톤 주최자가 진행 상황을 추적하려고 여는 커밋시티. 핵심 기능은 딱 하나, 진행 상황 버튼을 누르면 진척 사항이 나온다. 첫 화면에는 조별 진척과 개발, 디자인, 기획, 문서 네 분류의 진행 상황이 보인다.
- 핵심 기능 1개: "진행 상황 보기" 버튼을 누르면 조별 도시가 커밋에 따라 지어지는 모습이 재생된다.
- 누가 쓰나: 해커톤 운영진. 어느 조가 잘 가고 있고 어느 조가 막혔는지 보고, 먼저 찾아가 물어볼 조를 고른다.

## 정한 것

| 항목 | 내용 |
|---|---|
| 도시 | 조 하나가 도시 하나다. 예시로 네 조만 보여 준다 |
| 네 구역 | 개발, 디자인, 기획, 문서. 네 구역이 고르게 차야 전체 진척이 오른다 |
| 건물 | 커밋이 쌓이면 구역의 레벨(0~10)이 오르고 건물이 커진다. 개발은 아파트, 문서는 표지판처럼 구역마다 건물이 다르다 |
| 충돌 | 같은 파일을 동시에 고쳐 충돌이 나면 그 구역 점수가 깎이고 건물이 무너진다 |
| 부스트 | 짧은 시간에 많이 올리면 점수를 더 준다 |
| 시연 | 예시 데이터로 한다. 3시간의 진행을 1배, 2배, 5배, 10배로 재생한다 |
| 실제 데이터 | GitHub API에서 커밋 목록을 읽는 것이 본래 구상이다. 오늘 시연에는 연결하지 않는다 |

점수 규칙의 숫자는 `src/lib/sim.ts`의 `RULES`에, 예시 조와 커밋은 `src/data/events.ts`에 있습니다.

## 화면, 파일, 담당

화면은 레이스 하나로 통일했습니다. 구성의 기준은 조원이 만든 와이어프레임입니다.

| 화면 | 이 화면에서 하는 일 | 파일 | 상태 |
|---|---|---|---|
| 레이스 (첫 화면) | 순위 타워, S자 트랙, 실시간 중계, 조별 파트 주행 기록 | `src/pages/Home.tsx`, `src/components/race/` | 머지됨 |

에셋(펭귄 등)은 `public/images/race/`에 넣고 `src/lib/raceAssets.ts`에서 연결합니다.

## 역할

이름은 기획서에 있습니다. 여기에는 역할과 레포에서 닿는 곳만 적습니다.

| 역할 | 레포에서 하는 일 |
|---|---|
| 조장(개발) | 구조, 머지, 배포, 점수 규칙과 예시 데이터 |
| 기획 | 점수 규칙의 숫자와 시연 순서를 정해 조장에게 전달 |
| 와이어프레임 | 고른 시안의 배치를 정하고 화면 파일을 다듬음 |
| 에셋 수집 | 도시와 건물 이미지를 `public/images/`에 넣음 |
| 조별 보드 | 판넬 작성 |
| 발표 | 1분 스피치와 시연 조작 |

## 하지 않기로 한 것

- 실제 GitHub API 연결과 로그인 (시연 뒤에 붙입니다. 붙일 때는 Vercel 서버 함수 같은 클라우드에 두고, 키는 서버 환경 변수에만 넣습니다)
- 아이템, 부스터 구매 같은 게임 요소
- 조를 눌러 들어가는 상세 화면
