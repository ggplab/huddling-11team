# 오늘 실험 규칙

2026-11-14 현장 강의안에서 조별 실험에 해당하는 내용을 정리했습니다. 이 문서와 운영진 안내가 다르면 운영진 안내를 따릅니다.

## 목표

**팀당 배포 링크 1개를 제출합니다.** "내가 다음 주에도 열어 볼 것"을 만들어 인터넷 주소로 열리게 하는 것이 오늘의 목표입니다.

| 조건 | 뜻 |
|---|---|
| 온라인에서 열린다 | 배포 링크를 누구나 열 수 있다 |
| 명확한 기능 1개가 동작한다 | 버튼을 누르면 약속한 결과가 나온다 |
| 1분 스피치와 투표 | "내가 쓰고 싶은 서비스"에 투표한다 |

## 원칙 네 가지

1. **핵심 기능은 1개만.** 설명에 "그리고"가 들어가면 기능이 2개입니다. 하나만 남깁니다.
2. **꼭 다 같이 참여하기.** 모두가 역할을 하나씩 갖습니다.
3. **조별 보드 작성도 함께.** 1분 스피치에 쓰는 조별 보드(판넬)도 같이 완성합니다.
4. **모르면 손 번쩍.** 오래 붙드는 것이 가장 큰 시간 낭비입니다.

## 트랙

| 트랙 | 주제 | 설명 |
|---|---|---|
| A | 에이전트 서비스 | AI가 읽고, 정리하고, 대신 답해 주는 서비스 |
| B | API 연동 서비스 | 날씨, 지하철, 공휴일 같은 실제 데이터를 가져와 쓰는 서비스 |
| C | 미니 게임 | 출퇴근, 점심 시간 등 쉬는 시간에 하고 싶은 게임 |
| D | 자유 | 위 셋에 안 맞지만 꼭 만들고 싶은 것 |

## 기획하는 법

**아이디어를 찾는 질문 3개**

1. 이번 주에 귀찮았던 일
2. 휴대폰 메모장에 쌓여 있는 것
3. 친구에게 자주 물어보는 것

**한 줄 기획 템플릿.** 빈칸을 채우면 그대로 AI에게 주는 첫 요청이 됩니다.

> (누가) (언제) (무엇을 하려고) 여는 (서비스 이름). 핵심 기능은 딱 하나, (버튼을 누르면 무엇이 나온다). 첫 화면에는 (보이는 것 3가지)가 있다.

**기능이 하나인지 확인하기**

| 예 | 판정 |
|---|---|
| 우산 챙겨 알림: 출근 전에 동네를 고르면 12시간 비 올 확률과 "우산 챙겨 / 안 챙겨도 돼"가 크게 나온다 | 좋은 예 |
| 올인원 생활 비서: 날씨, 일정, 가계부, 식단을 한 번에 | 줄여야 하는 예. 기능이 4개라 시간 안에 하나도 끝나지 않는다 |

**좋은 요청의 4요소**: 누가 쓰는지, 무엇을 만드는지, 어떻게 만드는지, 끝나면 무엇을 알려 줄지.

**만드는 순서**: 한 번에 하나만 요청해 만들고, "완료"라고 해도 직접 눌러 확인하고, 본 그대로 말해 고치고, 잘 되면 내 브랜치에 올립니다.

## 화면만으로 되는가, 서버가 필요한가

| 구분 | 해당하는 경우 |
|---|---|
| 화면 파일만으로 끝 | 나 혼자 즐기는 간단한 게임, 기록이 남지 않는 일회용 게임 |
| 서버가 필요 | 랭킹이 저장되는 게임, 로그인이 필요한 서비스, 키가 필요한 API나 AI 호출 |

에이전트 서비스는 AI 모델의 API로 만듭니다. 강의안은 Gemini API를 대표 예로 듭니다.

## 팀 규칙

| 규칙 | 내용 |
|---|---|
| main에 직접 올리지 않기 | 브랜치에서 작업하고 PR을 올립니다 |
| 파일을 나눠 맡기 | 같은 파일을 동시에 고치면 충돌이 납니다 |
| 작게, 자주 합치기 | 30분에 한 번은 PR을 올립니다 |
| 머지는 조장 한 명만 | Vercel 배포도 조장만 할 수 있습니다 |

`CLAUDE.md`와 `AGENTS.md`에 담당 파일, 브랜치 규칙, 금지 사항을 적어 두면 Claude와 Codex를 섞어 써도 같은 규칙을 지킵니다. 이 레포에는 두 파일이 이미 있습니다.

**시작 순서**

1. 조장과 조원 모두 조별 레포를 클론합니다.
2. 조장이 첫 구조를 짜고 가장 먼저 푸시합니다.
3. 조원은 그 구조를 내려받고(풀), 브랜치를 만들어 작업하고 PR을 올립니다.

**역할 나누기.** 강의안의 예시는 파일 종류로 나눕니다(화면 담당 `index.html`과 `style.css`, 기능 담당 `app.js`와 `api/`, 기획과 발표 담당 `data.js`). 우리 조는 화면 단위로 나눕니다(한 사람이 `src/pages/`의 파일 하나). 같은 파일을 두 사람이 고치지 않는다는 원리는 같습니다.

## API를 쓸 때

**키 관리**

- API 키와 Supabase 키는 `.env` 파일에 모읍니다. 절대 노출되면 안 됩니다.
- `.env`는 `.gitignore`에 적어 커밋과 푸시가 되지 않게 합니다. 이 레포는 이미 적어 두었습니다.
- 키를 깃허브에 올리면 안 됩니다.

**주의 사항 5가지**

1. 승인받은 뒤에도 바로 쓸 수 없는 API가 있습니다.
2. API 키를 노출하지 않습니다.
3. 국가나 지역에 따라 사용할 수 없는 API가 있습니다.
4. 응답이 XML인 API가 많습니다. JSON으로 받으면 코드가 간결해집니다.
5. 오류가 났는데도 성공(200)처럼 오는 경우가 있어 응답 내용까지 확인합니다.

CORS 오류가 나면 "이 API 호출을 `api/` 함수로 옮겨 줘"라고 요청합니다. 데이터를 먼저 보고 화면은 나중에 정합니다.

**강의안이 추천한 API**

| 묶음 | 이름 |
|---|---|
| 가입 없이 바로 쓰는 것 | Open-Meteo(날씨), Frankfurter(환율), Nager.Date(공휴일), 위키백과 요약, Open Library(책), REST Countries(나라 정보), Sunrise-Sunset(일출과 일몰) |
| 취향과 재미 | TheMealDB, Open Food Facts, PokeAPI, Open Trivia DB, Deck of Cards, 메트로폴리탄 미술관, 시카고 미술관, Dog CEO |
| 국내 데이터 | 서울 실시간 지하철 도착, 따릉이 대여소 현황, 서울시 문화행사 정보, 기상청 단기예보, 에어코리아 대기오염정보, 한국천문연구원 특일 정보, 한국관광공사 TourAPI, 식품영양성분 DB, KOBIS 영화 박스오피스, KOPIS 공연예술통합전산망 |

국내 데이터 API는 호출 횟수 제한이 있거나 발급 직후 바로 쓰지 못할 수 있습니다. 강의안에 공공데이터포털 점검 공지 화면도 실려 있으니, 고르기 전에 실제로 호출되는지 먼저 확인합니다.

## 게임 트랙을 고르면

- 한 판을 먼저 정합니다. 조작, 목표, 끝나는 조건, 한 판 길이를 정하고 짧은 것을 고릅니다.
- 그래픽, 서버 연동(랭킹, 로그인), 추가 요소(소리, 아이템)는 우선순위를 낮춥니다.
- 그림 없이 도형이나 글자만으로 한 판이 끝까지 도는 판을 먼저 만듭니다.
- 속도, 점수, 시간 같은 숫자는 한 파일에 모읍니다.

## 자주 막히는 곳

10분 넘게 막히면 손을 듭니다. 운영진에게는 하려던 것, 보낸 요청, 화면 전체를 보여 줍니다.

| 증상 | 해결 |
|---|---|
| 배포 링크가 404 | `index.html`이 저장소 맨 위에 있는지 확인합니다 |
| 내 변경이 배포에 안 보인다 | PR이 main에 머지됐는지 확인합니다. 푸시만 하면 미리보기에만 반영됩니다 |
| 푸시가 rejected | "최신 내용을 받아서 합친 뒤 다시 푸시해 줘" |
| 충돌(conflict) | "두 사람 변경을 모두 살려서 해결해 줘"라고 한 뒤 미리보기로 확인합니다 |
| Gemini 429 오류 | 무료 한도 초과입니다. 다른 팀원 키로 바꾸고 다시 배포합니다 |
| 파일이 엉뚱한 곳에 생겼다 | 열린 폴더를 확인하고, worktree를 끄고(Local) 새로 시작합니다 |
| 사용량 한도 | 브랜치를 푸시하고 다른 앱이나 다른 팀원이 이어받습니다 |
