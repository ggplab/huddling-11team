# 인프라 정리

## 데이터가 흐르는 길

| 단계 | 하는 일 | 위치 |
|---|---|---|
| 1 | GitHub API에서 조별 레포 15개의 커밋과 PR을 읽는다 | 조직 `huddlingclub` |
| 2 | 수집기가 구역(개발, 디자인, 기획, 문서)을 나눠 정리본을 만든다 | `scripts/collect.mjs` |
| 3 | 정리본을 정적 파일로 둔다 | `public/data/snapshot.json` |
| 4 | 화면이 정적 파일을 읽어 그린다 | Vercel 정적 배포 |
| 덤 | 화면이 `/api/live`로 가벼운 현재값(커밋 수, 마지막 커밋, PR 수)을 받아 숫자만 덮는다 | `api/live.js` |

시연은 저장해 둔 정리본으로 한다. `/api/live`는 덤이고, 실패해도 화면은 정리본으로 돈다.

## 어디서 무엇이 도는가

| 일 | 도는 곳 | 비고 |
|---|---|---|
| 화면 | Vercel | 정적 배포 |
| `/api/live` 함수 | Vercel | 환경 변수 `GITHUB_TOKEN` 필요 |
| 10분 주기 수집 | GitHub Actions | `.github/workflows/collect.yml`, 아직 한 번도 실행 안 됨 |
| 맥미니, 집 네트워크 | 쓰지 않음 | 집 네트워크가 불안정해서 뺐다 |

## 조장이 손으로 할 일 (순서대로)

| 순서 | 할 일 |
|---|---|
| 1 | Vercel에서 이 레포를 불러온다 |
| 2 | 프로젝트 설정의 환경 변수에 `GITHUB_TOKEN`을 넣는다. 이름을 `VITE_`로 시작하지 않는다. 공개 레포 읽기 전용 토큰이면 충분하다 |
| 3 | 다시 배포한다. 환경 변수는 다음 배포부터 적용된다 |
| 4 | `<배포주소>/api/live`를 열어 `"ok":true`와 팀 15개가 보이는지 확인한다 |
| 5 | 조직에서 Actions가 허용되어 있으면 Actions 탭에서 `collect`를 한 번 수동 실행해 확인한다 |

## 고장 났을 때

| 상황 | `/api/live` 응답 | 화면 |
|---|---|---|
| 토큰 없음 | `ok:false, reason:"no-token"` | 정적 정리본으로 돈다 |
| GitHub 오류(15개 전부 실패) | `ok:false, reason:"github-error"` | 정적 정리본으로 돈다 |
| 일부 레포만 실패 | `ok:true`, 해당 조에 `error:true` | 그 조만 정리본 값을 쓴다 |
| 호출 한도 초과 | 위 오류와 같이 처리된다 | 정적 정리본으로 돈다 |
| 일시적 네트워크 끊김 | 호출당 2번 다시 시도한다 | 영향 없음 |

응답에는 `fallback: "/data/snapshot.json"`이 들어 있다. 화면 쪽에서 이 값으로 물러나는 처리는 화면 담당 소관이다.

## 비용과 한도

| 항목 | 내용 |
|---|---|
| 함수 호출 수 | `/api/live` 한 번에 GitHub 호출 30번(15조 x 2). 캐시 `s-maxage=60`이라 같은 주소는 60초 동안 재사용된다 |
| GitHub 토큰 한도 | 미확인 |
| Vercel 요금제별 가격과 함수 실행 시간 한도 | 미확인 |
| GitHub Actions 무료 분 수 | 미확인 |
